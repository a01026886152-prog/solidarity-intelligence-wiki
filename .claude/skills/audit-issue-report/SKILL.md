# 행정사무감사 쟁점보고서 작성

자료를 받아 **기관별 쟁점 → 근거 → 질의안** 순서의 보고서를 쓴다. 질의안은 감사장에서 그대로 읽을 수 있는 문장이어야 하고, 모든 수치와 사실은 받은 자료의 어느 문서에서 왔는지 밝힌다.

## 1단계. 설정 읽기

1. `uijeong/profile.md`와 `uijeong/knowledge/committee-2026.md`를 읽는다.
2. 프로필의 **관점**이나 **의원명**이 비어 있으면 AskUserQuestion으로 묻고 `profile.md`에 저장한다.

## 2단계. 자료 받기와 추출

1. 사용자가 올린 파일 경로(메시지의 `@경로`)와 `uijeong/inbox/`의 파일을 모은다. 자료가 하나도 없으면 무엇을 올려야 하는지 안내하고 멈춘다(업무보고, 행감 계획서, 요구자료 답변, 예산서, 기사 등).
2. 의존성이 없으면 설치한다: `pip install -q -r uijeong/scripts/requirements.txt`
3. 추출한다. 추출본은 스크래치패드(없으면 `uijeong/inbox/_text/`)에 둔다.
   ```bash
   python3 -I uijeong/scripts/extract.py <파일들> --out <추출폴더>
   ```
4. 추출본마다 **문서 성격**을 한 줄로 분류한다: 공식(계획서·업무보고·예산서·요구자료 답변) / 정당·단체 자료 / 언론 / 기타. 이 분류는 보고서의 근거 표기에 그대로 쓴다.
5. 큰 문서는 목차와 장 제목으로 구조를 먼저 파악한 뒤, 필요한 부분만 읽는다.

## 3단계. 범위 묻기

AskUserQuestion 한 번에 아래를 묻는다(자료에서 답이 분명한 것은 빼고, 추천 선택지를 첫째에 둔다).

- **대상 기관**: 위원회 소관 기관 중 어디를 다룰지 (복수 선택, 자료에 등장한 기관을 추천)
- **질의 의원**: 프로필 의원 단독 / 위원회 공동 자료(위원별 배분 없이)
- **분량**: 기관당 쟁점 3~5개 핵심형(추천) / 자료의 쟁점 전부 망라형
- **초점**: 예산 집행·실적 / 제도·절차 위법성 / 시민 피해·현장 / 전년도 지적사항 이행 (복수 선택)

## 4단계. 쟁점 추출과 분석

기관마다 아래 순서로 분석한다. 다른 기관 소관인 쟁점은 그 기관으로 옮기고, 위원회 소관 밖이면 "소관 확인 필요"로 따로 모은다.

1. **사업 현황**: 사업명, 담당부서, 예산, 근거, 추진경과. 자료에 있는 것만 쓴다.
2. **문제점**: 아래 렌즈로 본다. 근거가 있는 렌즈만 쓴다.
   - 계획 대비 실적(달성률, 집행률, 불용·이월)
   - 예산 증감과 그 이유
   - 절차·법령 위반 소지(위임 범위, 심의 생략, 협약 변경)
   - 시민 피해·형평(누가 손해를 보는가)
   - 통계·보고 방식의 착시(기준 변경, 합산, 기준일 차이)
   - 전년도 행감·감사원 지적사항 미이행
   - 유사·중복 사업, 민간 특혜
3. **집행부 예상 답변과 반박**: 집행부가 내놓을 논리를 한 줄로 쓰고, 그에 맞설 근거를 붙인다.
4. **질의안**: 쟁점마다 2~4개. 아래 형식을 지킨다.
   - 사실 확인 질문 → 원인 추궁 질문 → 대책·약속 요구 순서
   - 예/아니오나 숫자로 답할 수밖에 없게 묻는다
   - 질문마다 근거 문서와 수치를 괄호로 단다
5. **요구 자료**: 감사 전·중에 추가로 받아야 할 자료 목록.
6. **시정·처리 요구 초안**: 감사결과보고서에 넣을 한 줄 요구.

정당·단체 자료에서 온 주장은 "○○ 자료에 따르면"으로 출처를 밝히고, 공식 자료로 뒷받침되면 함께 적는다. 공식 자료로 확인되지 않는 수치는 `[공식자료 확인 필요]`를 붙인다.

## 5단계. 작성

[template.md](template.md) 구조를 따른다.
- 관점이 **의원실**이면 질의 화자는 "본 의원", 관점이 **시민단체**면 질의안을 "의원 제안 질의"로 쓰고 끝에 "의원 제안 요지"를 붙인다.
- 어조는 프로필을 따른다. 인신공격, 확인되지 않은 의혹 단정, 정치적 수사는 쓰지 않는다.

## 6단계. 자체 검수 (저장 전)

아래를 하나씩 확인하고, 틀린 곳은 고친다.
- [ ] 보고서의 모든 수치를 추출본에서 다시 찾아 대조했다(`grep`). 찾지 못한 수치는 지우거나 `[확인 필요]`를 붙였다.
- [ ] 법령 조문은 `uijeong/knowledge/legal-basis.md` 또는 받은 자료에 있는 것만 썼고, 그 밖의 조문은 `[조문 확인 필요]`를 붙였다.
- [ ] 쟁점마다 출처 문서가 있다.
- [ ] 질의안이 실제로 소관 기관에게 물을 수 있는 내용이다.
- [ ] 개인정보(일반인 실명, 연락처)가 없다.

## 7단계. 저장과 전달

1. `uijeong/outputs/audit/YYYY-MM-DD-<기관약칭들>.md`로 저장한다(오늘 날짜).
2. 프로필의 **출력 형식**대로 변환한다(기본: 한글 HWPX, 필요하면 DOCX도):
   ```bash
   python3 uijeong/scripts/md2hwpx.py uijeong/outputs/audit/<파일>.md
   python3 uijeong/scripts/md2docx.py uijeong/outputs/audit/<파일>.md   # DOCX도 원할 때
   ```
3. SendUserFile로 HWPX(와 DOCX)를 보낸다(`display: attach`).
4. 사용자에게 기관별 쟁점 수, 확인 필요 표시 개수, 추가로 받으면 좋을 자료를 짧게 알린다.
5. 감사 아카이브 허브(`wiki/field-notes/2026-seoul-housing-committee-audit/README.md`)의 쟁점 추적표에 새 쟁점을 추가할지 묻는다.
