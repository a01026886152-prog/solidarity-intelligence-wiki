> 작성일: 2026-10-29 | 작성: 총비서 해일심(Claude) | 검수: 랑랑별
> 근거: 2026-10-25~29 이 저장소 작업 대화와 사용자 화면 사진 [근거 1]. 실제 사용량 수치는 보지 못했다. 아래 원인은 **작업 방식에서 추정한 것**이다.

## 한 줄 요약

규칙 파일이 길어서가 아니다. **비싼 모델로, 긴 대화에 화면 사진을 쌓아 가며, 검수 AI와 Chrome 작업을 여러 창에서 동시에** 돌려서 빨리 닳는 것으로 보인다.

## 이번에 고친 것 (해일심이 저장소에 반영)

1. **랑랑별은 더 가벼운 모델(Sonnet)로** 돌린다. 검수는 대조·확인 작업이라 충분하다고 본다. — `.claude/agents/rangrang-byeol.md` 맨 위 `model: sonnet` [근거 8]. **새 세션부터** 적용되고, 해일심이 부를 때 모델을 따로 지정하면 그쪽이 우선한다. 실제로 Sonnet으로 도는지는 아직 확인하지 못했다(이 문서의 검수는 바꾸기 전 설정으로 돌았다).
2. **검수는 넘기는 문서에만, 재검수는 고친 곳과 그 앞뒤 문단, 바뀐 값이 나오는 모든 곳만** — `CLAUDE.md` '토큰 아끼기' 1·2번.
3. **Chrome은 글로 읽기**: 화면 사진은 버튼 찾을 때만, 자료 목록은 '자료 안에서 찾기'로 좁히기 — `CLAUDE.md` '토큰 아끼기' 3번, `/policy-research` 3단계 9번
4. **큰 문건은 근거 쪽만 읽기**, 대화가 길어지면 `정리해` 후 새 세션 권하기 — `CLAUDE.md` '토큰 아끼기' 4·5번

## 정확도는 그대로인가 (2026-10-29 덧붙임)

아끼는 규칙이 자료 누락이나 검수 오차를 만들 수 있는 곳을 다시 살펴, 아래처럼 막았다. 원칙은 `CLAUDE.md` '토큰 아끼기' 첫 문단의 **정확도가 먼저다**.

| 걱정 | 위험 | 막은 방법 |
|---|---|---|
| '자료 안에서 찾기'로만 찾으면 빠지는 자료 | 이 검색은 '완료'가 아닌 파일을 잡지 못할 수 있다(추정, 시험 안 함). 10-28 화면에서 주택실 카드는 '자료 1586건 · 읽는 중 1026', 자료 목록은 '완료 527건'이었다 [근거 2] | 파일 이름 목록도 글로 훑어 더하고, 카드 건수와 맞춰 보고, 결과 문서에 못 본 범위('k건은 제목으로만 골랐음')를 적음 |
| 랑랑별을 Sonnet으로 돌리면 놓치는 오류 | 작은 모델이 미묘한 오류를 더 놓칠 수 있다(추정) | 의정 문서(보고서·브리핑·질의서·조례안·발언 원고·사업계획서·보도자료)는 Opus로 검수 |
| 재검수를 고친 곳만 하면 놓치는 오류 | 숫자 하나를 고치면 요지·표·근거 목록의 같은 숫자가 어긋날 수 있다 | 바뀐 숫자·이름·날짜가 나오는 모든 곳을 함께 보게 함 |
| 큰 문건을 필요한 쪽만 읽으면 놓치는 조건 | 표의 단위·기준일·각주를 빼면 숫자를 잘못 쓸 수 있다 | 숫자를 쓸 때는 단위·기준일·각주와 같은 절 앞뒤 문단을 함께 읽음 |

1차 검수(랑랑별이 문서 전체를 처음부터 보는 것)와 근거 표시·발췌집 규칙은 바꾸지 않았다.

### 그래도 결과물이 부족해 보이면

1. **"꼼꼼하게"라고 말한다.** 아끼기 규칙을 끄고 Opus 검수, 문서 전체 재검수, 자료 목록·문건 전체 읽기로 한다 (`CLAUDE.md` '토큰 아끼기' 5번).
2. **"빠진 자료 있는지 확인해줘"** — 검색 범위 줄의 '제목으로만 골랐음' 파일을 다시 보게 한다.
3. **"랑랑별 전체 재검수"** — 고친 곳만이 아니라 처음부터 다시 검수한다.
4. **숫자는 직접 대조한다.** 발췌집(`uijeong/outputs/research/…발췌.md`)의 원문과 문서의 숫자 두세 개를 맞춰 본다.
5. 문제를 찾으면 알려 주면 규칙에 반영한다.

## 사용자가 하면 효과가 큰 것

1. **작업 하나에 세션 하나.** 주제가 바뀌면 `정리해` → 새 세션에서 "핸드오버 읽고 이어서 하자". 가장 효과가 크다.
2. **화면 사진은 필요한 부분만.** 오류 문구는 사진 대신 글자를 복사해 붙여 넣는다. 사진이 필요하면 해당 창만 찍는다(**Alt + PrtSc**는 지금 창만 찍는다).
3. **동시에 여러 창을 돌리지 않는다.** 쓰지 않는 Chrome 패널 작업은 멈추고(■ 버튼), 끝난 세션은 닫는다.
4. **쉬운 일은 작은 모델로.** 입력창 아래 모델 이름(Opus 5.5)을 눌러 **Sonnet**으로 바꾼다. 안내·간단한 질문·파일 정리는 Sonnet, 질의서·조례안 작성은 Opus.
5. **사용량 확인**: 화면에 '주간 사용량 한도 초과 임박'이 뜨면 큰 작업(질의서 여러 편, Chrome 대량 검색)은 알림에 적힌 초기화 시각(10-28 화면에서는 '10월 29일(목) 오전 3:00') 뒤로 미룬다. Claude Code 입력창에 `/usage`를 넣으면 지금 사용량을 볼 수 있다 [근거 4].
