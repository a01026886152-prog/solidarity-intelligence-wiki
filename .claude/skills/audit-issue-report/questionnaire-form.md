# 박이강 의원 행정사무감사 질의서 양식 (국회 비서관 양식)

## 2026 행감 최종본 구성 (2026-10-31 사용자 확정, 이 구성을 먼저 따른다)

사용자가 확정한 최종본 아홉 편(주택실 3편, SH 4편, 디지털도시국 1편, AI재단 1편)의 공통 구성이다.

최종본 아홉 편에서 보이는 주제 고르는 법(2026-10-31 정리)
- 정당 핵심과제·언론 쟁점을 옮기지 않는다. 전문위원실 「주요 감사방향」, 박이강 부위원장 개별 요구자료 답변, 공통 요구자료, 집행부 내부 계획서·공문·이사회 회의록에서 쟁점을 찾는다.
- 숫자 뒤의 **사람**을 묻는다: 정책 수치(공급·이주·지원 실적)마다 그 숫자에서 빠지거나 밀려난 사람이 누구인지 묻는다.
- 집행부 스스로의 문서끼리 맞지 않는 곳을 찾는다: 처리결과의 추진 상황과 실제 내용, 보고 시점별 일정, 같은 사업의 자료별 숫자, 계획서와 성과지표, "자료 없음" 답변과 실제 시스템 기능.
- 뒤 네 편은 보도 인용 없이 행감 자료실 자료만으로 썼다. 보도는 자료실에 없는 사실(국정감사 발언 등)에만 쓴다.
- 문단 제목·▶ 문단은 가치 판단을 분명히 한다.
- 1절은 **실태**로 연다: 제도·조항을 설명하기 전에 피해·대상이 몇 명(몇 가구, 몇 건)인지부터 센다. 공통 요구자료의 민원·소송 현황이 출발점이 될 수 있다.
- **바꿀 권한과 그 근거를 본다**: 문제가 법·시행령·시행규칙(서식)·조례·내규 가운데 어디에 걸려 있는지 법령 위계와 관련 판결로 확인하고, 권한이 있는 기관을 향해 묻는다.
- 예산은 **증감·집행률·다음 해 예산**까지 본다.

```
{기관명}
{헤드라인 제목}                         ← 부제가 있으면 '_부제'로 이어 붙임
담당 : 정책지원관 {이름}
※ 참고자료 : {이 질의서가 쓴 행감 자료실 원자료 이름을 쉼표로 나열}   ← 맨 위에 한 줄

○ 질의 요지
- {5~7줄. 줄마다 숫자와 (출처 자료 이름)}

1. {문단 제목 — 그 자체로 주장이 되는 짧은 문장}
【① 의원 주장】                         ← 라벨은 첫 문단에서만 쓰고 이후 문단은 같은 순서로 라벨 없이 이어 써도 됨
❍ {주장}  - {사실·수치, (출처 자료 이름)}
【② 근거자료 — 행감 자료실】
[출처: {카드 이름} > {파일 이름 그대로}, {쪽·시트·항목}] [붙임 n 참고]
<{자료 이름} 중>                         ← 원문 인용 블록: 원문 문장은 따옴표로 글자 그대로, 표는 필요한 줄만, 계산이면 '(계산)' 표시
【참고 — 보도자료】
* {매체 날짜 「제목」}: {내용} — {자료실 원자료와 일치/불일치}
【③ PPT】

[표n] {제목} (PPT n)
(출처 : …)
☞ (사장·실장·국장·이사장) {질의}  - {보충 질의, 자료 제출 요구}

n. 요구 사항
▶ {가치 중심 강조 한 문단}

[붙임 자료]
[붙임 1] {원자료 이름} 중  ← 본문 인용의 원문 대목을 다시 모음(캡처 대신 원문 텍스트·표)
```

지키는 것
1. **근거는 행감 자료실 원자료가 먼저, 보도는 참고.** 보도 수치는 자료실 원자료와 대조해 "일치/다름"을 적는다. 자료실에 없는 것(국정감사 발언 등)은 "행감 자료에 없음 — 보도로 인용"이라고 적는다.
2. **숫자는 원자료 단위 그대로 확인하고 본문에서 반올림한다**(예: 백만원 단위 원자료 → 본문은 억원으로 반올림). 반올림한 보도 수치와 원자료가 다르면 원자료 기준으로 말한다.
3. **추정은 추정으로**: 기회비용 계산(예: '이 금액이면 공공임대 몇 가구')처럼 가치 중심 주장은 넣되 계산식·기준 단가·'추정'을 함께 적고, 자료실에 있는 실제 단가(위원 개별 요구자료 등)로 다시 계산해 덧붙인다.
4. **집행부 내부 문서의 자기 모순을 질의로 만든다**: 이사회 회의록 발언, 조건부 의결 조건, 처리결과 '추진 완료', 내부 공문 경고 문구를 원문 그대로 인용해 "조건은 이행됐는가", "추진 완료가 맞는가"를 묻는다.
5. **비공개 표시 자료**(정보공개법 비공개 사유 표시가 붙은 자료)를 인용하면 그 사실을 붙임에 표시하고, 질의서 전체를 GitHub에 올리지 않는다.
6. 근거 자료 목록 표와 검수 기록은 최종본에서 빼도 된다(출력본 기준). 작업용 Markdown에는 남긴다.
7. **'확인 필요'는 같은 기관의 다른 제출자료로 먼저 푼다**(공통 요구자료의 민원·소송·용역·위원회 현황, 다른 위원의 개별 요구자료, 회의록). 그래도 남으면 질의로 바꾼다.
8. **짝이 되는 숫자를 섞지 않는다**: 약정/실행, 매출/이익, 예산/집행, 계획/실적, 호/세대/가구(실거주).
9. **집행부 집계는 원문 목록으로 다시 센다**(개최 횟수는 회의록, 계약 건수는 계약 목록, 의결은 의결한 회차). 위법을 떠올리게 하는 표현은 입력 오류 같은 다른 설명을 먼저 빼고 쓴다.
10. **요구는 집행부가 실제로 할 수 있는 크기로** 한다: 전수 점검보다 시범조사와 지표 도입 시점, 책임은 단정하지 않고 판단 자료 제출부터.
11. **쪽수는 인쇄 쪽 번호**로 적는다. 여러 파일을 묶은 PDF면 '묶음 전체 n쪽'이라고 적는다.
12. **출력 전 점검**: 고친 값은 요지·표·PPT·붙임에서 모두 다시 찾아 고치고, 표 칸이 서로 바뀌지 않았는지 보고, 옛 근거 기호와 작업용 '확인 필요'를 검색해 정리한다.
13. **새 질의서는 먼저 같은 기관의 최종본을 열어** 깊이와 문체를 맞춘다(`uijeong/outputs/research/final-2026/`, GitHub 제외 폴더라 PC에만 있음).
14. **쟁점은 전문위원실 감사방향, 의원 개별 요구자료, 내부 문서에서 찾는다.**
15. **질의마다 먼저 확인한다**: '이 숫자 뒤에 누가 있는가', '집행부 문서끼리 어디가 어긋나는가'.
16. **보도는 자료실에 없는 사실에만 쓴다.**

박이강 의원 질의서는 이 양식으로 쓴다. 의원실이 국회 비서관 시절 쓰던 질의서 세 건(2019~2021년, 한글 파일)에서 **구성과 문체만** 뽑은 것이다. 그 질의서들의 내용(부처, 사업, 수치)은 쓰지 않는다. 쟁점 하나에 질의서 한 편을 쓴다.

## 구성

```
{기관명}                                   ← 첫 줄. 예: 주택실, SH공사, 미래공간기획관, 디지털도시국, 서울AI재단
{헤드라인 제목}                             ← 언론 기사 제목처럼 한 줄. 핵심 수치나 대비를 넣는다.
담당 : {작성자} 비서                         ← 작성자를 모르면 이 줄은 비운다.

○ 질의 요지
- {쟁점을 5~7줄로. 무엇이 문제이고, 근거 수치가 무엇이고, 무엇을 요구할지}

❍ {현황 문단 — 사실과 수치. 개조식 '~임', '~함'으로 끝낸다}
  {이어지는 설명은 들여 쓴 줄로}

[표1] {표 제목}
| 구분 | … |
|------|---|
(출처 : {자료 이름 — 저장 위치, 쪽·표})

❍ {문제 제기 문단 — "그러나 ~를 살펴보니 ~가 드러났음"}

☞ {대상}, {질의 문장}?                         ← 대상: 실장 / 사장 / 기획관 / 국장 / 이사장, 또는 (기관 약칭)
- {질의를 받치는 사실·수치 한두 줄}
※ {보충 정보·출처 메모}

▶ {핵심 결론이나 강조 문단}                     ← 원본에서 특수 기호로 표시된 강조 문단 자리

☞ {대상}, {다음 질의}?
…

① {대안 소제목}
  {대안 설명}
② {대안 소제목}
  {대안 설명}

☞ {대상}, {대안을 받아들이고 계획을 보고해 달라는 마무리 요구}
- {마무리 한두 줄: "~를 명심하기 바람", "~를 검토해주시기 바람"}
```

## 문체

1. **제목은 헤드라인으로**: 숫자와 대비로 한눈에 쟁점이 보이게 쓴다. 따옴표로 꼬집는 말을 쓸 수 있다. 근거 없는 표현은 쓰지 않는다.
2. **본문은 개조식**: ❍·- 줄은 '~임', '~함', '~했음'으로 끝낸다. 한 줄에 사실 하나.
3. **질의는 ☞로 시작**하고 대상을 먼저 부른다(예: `☞ 사장,` / `☞ (SH공사)`). 예/아니오나 숫자로 답할 수밖에 없게 묻는다. 사실 확인 → 원인 추궁 → 대안·약속 요구 순서로 이어 간다.
4. **표에는 번호와 출처**: `[표n] 제목` 다음 표, 그 아래 `(출처 : …)`. 본문에서 `[표n]`으로 가리킨다.
5. **예상 답변 갈래**: 답에 따라 갈라지는 대목은 괄호로 적는다. 예: `- (사실이 아니라고 답할 경우) ~를 확인했음`
6. **마무리**는 보고·검토·시정 요구와 당부 한 줄로 끝낸다.
7. **호칭**: 서울시의회이므로 '장관' 대신 상대 직위(실장, 사장, 기획관, 국장, 이사장)를 쓴다.

## 근거 표시

양식의 `(출처 : …)`와 `※` 줄에는 `CLAUDE.md` '근거 자료 표시' 형식을 그대로 쓴다. 사교원 행감 자료실 자료는 `uijeong/knowledge/sakyowon-archive.md`대로 카드 이름·파일 이름·쪽·찾기어를 적는다. 질의서 끝에는 **근거 자료 목록**과 **검수 기록**을 붙인다(출력할 때 빼도 된다고 적어 둔다).

## 쓰지 않는 것

- 행감 자료실 카드 안에 올라와 있는 **다른 행정사무감사 질의서·쟁점보고서**(누가 미리 써 둔 질의서)의 문장. 사용자가 이번 질의서를 처음부터 새로 쓰라고 했기 때문이다. 원자료(요구자료 답변, 업무보고, 계획서, 계약서 등)만 근거로 쓴다. 이미 쓴 질의서를 근거로 삼고 싶으면 사용자에게 묻는다.
- 국회 시절 양식 문서들의 내용.
- 확인되지 않은 의혹의 단정, 인신공격.

## 한글 파일로 만들 때

`python3 uijeong/scripts/md2hwpx.py <파일>.md`로 만든다. 글꼴·표 모양은 원본 한글 양식과 같지 않을 수 있다. 원본 서식이 꼭 필요하면 한글에서 원본 양식 파일을 열고 본문을 붙여 넣으라고 안내한다.
