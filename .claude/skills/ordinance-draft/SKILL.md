# 법적 검토서 + 조례안 작성

**현황 진단 → 법적 근거 검토 → 조례안**의 순서로 쓴다. 법적 검토에서 막히는 지점(위임 근거 없음, 상위법 저촉, 단체장 권한 침해)이 나오면 조례안을 쓰기 전에 사용자에게 알리고 대안을 묻는다.

## 1단계. 설정 읽기

`uijeong/profile.md`, `uijeong/knowledge/committee-2026.md`, `uijeong/knowledge/legal-basis.md`를 읽는다. 관점·의원명이 비어 있으면 묻고 저장한다.

## 2단계. 자료 받기와 추출

[audit-issue-report 2단계](../audit-issue-report/SKILL.md)와 같다. 올린 자료가 없어도 사용자가 제도 아이디어를 말했으면 진행한다. 자료는 문서 성격(공식/정당·단체/언론/기타)을 분류한다.

## 3단계. 범위 묻기

AskUserQuestion 한 번에 묻는다(자료나 메시지에서 분명한 것은 뺀다).

- **유형**: 제정 / 일부개정 / 전부개정 (개정이면 현행 조례명과 현행 조문을 올려 달라고 한다)
- **도입하려는 제도의 핵심**: 누구에게(대상), 무엇을(지원·의무·기구·계획), 어떻게(방식)
- **강도**: 시장의 책무·계획 수립 중심(권고형) / 지원 사업 근거 / 주민 의무·제한 포함 — 의무·제한을 고르면 법률 위임 근거가 필요하다고 미리 알린다
- **재정**: 예산이 드는가, 대략 규모

## 4단계. 현황 진단

- 문제 현황: 자료의 수치와 사례. 자료에 없는 수치는 만들지 않는다.
- 현행 제도의 공백: 서울시가 지금 이 문제에 쓰는 수단(사업·조례·지침)과 빈틈.
- 다른 시·도 사례: 자료에 있거나 자치법규정보시스템(https://www.elis.go.kr)에서 확인한 것만 쓴다. 네트워크가 막혀 확인하지 못하면 "확인하지 못함"이라고 쓰고, 찾아볼 검색어를 남긴다.

## 5단계. 법적 검토

1. **근거 법령 찾기**: `legal-basis.md`의 분야별 법률에서 관련 법률을 고르고, 조례에 위임한 조항이 있는지 본다. 국가법령정보센터(https://www.law.go.kr)를 WebFetch로 확인할 수 있으면 확인하고, 못 하면 `[조문 확인 필요]`를 단다.
2. **상위법 저촉 체크리스트**: `legal-basis.md`의 7개 항목을 표로 하나씩 판단한다(적합 / 주의 / 저촉 우려, 근거 한 줄).
3. **중복 확인**: 같은 내용의 서울시 조례가 있는지. 있으면 제정 대신 개정을 제안한다.
4. **판단**: 저촉 우려가 하나라도 있으면 멈추고, 사용자에게 알린 뒤 대안(권고형으로 낮추기, 지원 근거로 바꾸기, 법률 개정 건의로 돌리기)을 AskUserQuestion으로 묻는다.

## 6단계. 조례안 작성

[template.md](template.md)를 따른다. 조문 작성 규칙:

- 제정 조례 기본 구성: 목적 → 정의 → 기본원칙·시장의 책무 → 계획 수립 → 실태조사 → 지원 사업 → 위원회(필요할 때만) → 협력·위탁 → 시행규칙 위임. 필요 없는 조는 넣지 않는다.
- 조문은 「○○법」 제○조에 따라 형식으로 근거를 밝힌다.
- "~하여야 한다"(의무)와 "~할 수 있다"(재량)를 구분한다. 시장에게 예산이 드는 의무를 지우면 단체장 권한 침해 논란이 생길 수 있으니 지원 사업은 원칙적으로 "할 수 있다"로 쓴다.
- 위원회를 새로 만들면 기존 위원회와 통합 가능성을 검토 의견에 적는다(위원회 남설 지적 대비).
- 개정안은 개정문("제○조제○항 중 "가"를 "나"로 한다.")과 신·구조문대비표를 모두 쓴다. 현행 조문을 받지 못했으면 개정문을 쓰지 말고 사용자에게 현행 조문을 요청한다.
- 부칙: 시행일, 필요하면 경과조치.

## 7단계. 비용추계서

- 재정이 드는 조항마다 비용을 추계한다. 추계 기간은 시행 연도부터 5년으로 하고, 단가·수량·산식을 밝힌다.
- 단가 근거는 자료, 서울시 유사 사업 예산, 공식 통계 순으로 찾는다. 근거가 없으면 빈칸으로 두고 `[단가 근거 필요]`를 단다.
- 재정이 들지 않으면 "비용추계 비대상" 사유를 쓴다. 의회 규정상 비용추계서 미첨부 기준은 `[규정 확인 필요]`로 표시한다.

## 8단계. 자체 검수

- [ ] 조례안 본문이 법적 검토 결론과 맞다(저촉 우려를 남긴 채 조문화하지 않았다).
- [ ] 인용한 모든 법령 조문이 `legal-basis.md`, 받은 자료, 또는 이번에 확인한 법령 원문에 있다. 나머지는 `[조문 확인 필요]`.
- [ ] 조 번호가 연속되고, 조문 안의 다른 조 인용이 맞다.
- [ ] 정의 조항의 용어가 본문에서 같은 뜻으로 쓰였다.
- [ ] 비용추계서 합계가 연차별 합과 맞다.
- [ ] 신·구조문대비표의 현행 조문이 받은 원문과 글자까지 같다.

## 9단계. 저장과 전달

1. `uijeong/outputs/ordinance/YYYY-MM-DD-<제도명>.md`
2. `python3 uijeong/scripts/md2docx.py <파일>.md` → SendUserFile(`display: attach`)
3. 사용자에게 알린다: 법적 검토 결론, 확인 필요 조문 수, 협의가 필요한 기관(집행부 부서, 사회보장협의 대상 여부 등), 입법예고 등 다음 절차.
