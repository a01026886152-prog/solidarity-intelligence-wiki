# 사업계획서(안) 작성

예산 심사에서 통과할 수 있게 **필요성 → 구조 → 돈 → 성과**를 갖춘 계획서를 쓴다. 산출근거와 성과지표는 숫자로 쓰고, 근거가 없는 숫자는 만들지 않는다.

## 1단계. 설정 읽기

`uijeong/profile.md`, `uijeong/knowledge/committee-2026.md`, `uijeong/knowledge/legal-basis.md`(재정·사업 표)를 읽는다. 비어 있는 설정은 묻고 저장한다.

## 2단계. 자료 받기와 추출

[audit-issue-report 2단계](../audit-issue-report/SKILL.md)와 같다. 예산서, 유사 사업 계획서, 통계, 연구보고서가 있으면 단가와 성과지표 근거로 쓴다.

## 3단계. 범위 묻기

AskUserQuestion 한 번에 묻는다.

- **사업 유형**: 신규 본사업 / 시범사업(대상지·기간 한정 후 확대 판단) / 기존 사업 확대
- **지원 방식**: 직접 수행 / 민간위탁 / 민간보조 / 출연기관(SH·서울AI재단 등) 수행 / 자치구 보조
- **규모와 기간**: 대상 수, 사업 기간(연차), 대략 예산 상한
- **소관 부서**: 자료에서 추정한 부서를 추천으로 둔다

## 4단계. 사업 설계

1. **필요성**: 문제 현황(수치·출처), 기존 사업으로 안 되는 이유, 법적 근거(조례·법률).
2. **목표**: 최종 목표 1개, 연차별 목표.
3. **사업내용**: 세부사업별 대상·선정기준·지원내용·지원방식.
4. **추진체계**: 주체별 역할(서울시 부서, 수행기관, 자치구, 민간), 협의체.
5. **유사·중복 검토**: 국가·서울시·자치구·교육청 유사 사업과 차별점. 중복이 크면 사용자에게 알린다.
6. **시범사업**이면: 대상지 선정기준, 기간, 비교집단 등 평가 설계, 본사업 확대 조건(정량 기준).

## 5단계. 소요예산

- **산출근거 표**: 세부사업 → 비목 → 단가 × 수량 × 기간 = 금액. 산식을 그대로 적는다.
- **단가 근거**: 받은 자료 → 서울시 유사 사업 예산 → 공식 통계·기준 순. 근거가 없으면 단가 칸을 비우고 `[단가 근거 필요]`.
- **예산과목**: 비목 이름에 통계목 후보를 적되(예: 민간경상사업보조, 민간위탁금, 연구용역비, 사무관리비), 코드와 적용 기준은 「지방자치단체 예산편성 운영기준」으로 확인하라고 `[편목 확인 필요]`를 단다.
- **연차별 소요와 재원**: 시비·국비·구비 구분, 국비 매칭이면 근거 사업.
- **사전 절차 체크**: 투자심사, 타당성조사, 사회보장제도 신설·변경 협의, 출연·출자 근거, 민간위탁 동의 등 해당 여부를 표로. 기준 금액은 `legal-basis.md`를 따르고 확정하지 못하면 `[기준 확인 필요]`.

## 6단계. 성과지표

- 지표마다: 지표명, 유형(투입/산출/결과), 산식, 기준치(출처), 연차별 목표치, 측정방법, 자료 출처.
- **결과지표를 최소 1개** 넣는다(참여자 수 같은 산출지표만으로 끝내지 않는다).
- 기준치가 없으면 "1차 연도 측정 후 설정"으로 쓰고 측정 계획을 적는다.

## 7단계. 작성과 자체 검수

[template.md](template.md)를 따른다. 저장 전 확인:
- [ ] 산출근거 표의 금액을 다시 계산했다(단가 × 수량 × 기간). `python3 -c`로 계산해 대조한다.
- [ ] 세부사업 합 = 연차별 합 = 총사업비.
- [ ] 재원 구성 합 = 총사업비.
- [ ] 모든 수치에 출처가 있거나 `[확인 필요]`가 붙어 있다.
- [ ] 성과지표에 결과지표가 있다.

## 8단계. 저장과 전달

1. `uijeong/outputs/project-plan/YYYY-MM-DD-<사업명>.md`
2. `python3 uijeong/scripts/md2docx.py <파일>.md` → SendUserFile(`display: attach`)
3. 사용자에게 알린다: 총사업비, 확인 필요 단가 수, 거쳐야 할 사전 절차, 예산 요구 시기(본예산·추경).
