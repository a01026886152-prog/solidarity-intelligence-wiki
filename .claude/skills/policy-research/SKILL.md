# 자료함 + 뉴스 검색 답변

질문 하나에 대해 **정책지원관 지원시스템 자료함**과 **뉴스기사**를 함께 검색하고, 두 출처를 구분해 표시한 답변을 쓴다. 자료함은 로그인이 필요하고 내부망 전용일 수 있다. 그래서 사용자 PC에서 도는 세션(Claude Desktop 앱 또는 `claude remote-control`)에서 Claude in Chrome이 연결되어 있어야 한다.

## 1단계. 설정 읽기

1. `uijeong/profile.md`를 읽는다. **지원시스템 주소**가 비어 있으면 AskUserQuestion으로 묻고 저장한다. 자료함 메뉴 위치도 알면 함께 적어 둔다.
2. 사용자가 질문을 밝히지 않았으면 무엇을 알고 싶은지 묻는다. 질문은 알맞은 검색어 2~4개로 나눈다(정식 사업명, 약칭, 관련 법령·조례명, 기관명).

## 2단계. 브라우저 확인

1. 시작하기 전에 `anthropic-skills:chrome-browser` 스킬을 읽는다. 도구는 ToolSearch 한 번으로 불러온다.
   ```
   select:mcp__claude-in-chrome__tabs_context_mcp,mcp__claude-in-chrome__tabs_create_mcp,mcp__claude-in-chrome__navigate,mcp__claude-in-chrome__read_page,mcp__claude-in-chrome__find,mcp__claude-in-chrome__computer,mcp__claude-in-chrome__get_page_text,mcp__claude-in-chrome__tabs_close_mcp
   ```
2. 도구가 없거나 확장 프로그램이 연결되지 않았으면 **멈추지 말고** 아래처럼 대신한다. 무엇이 빠졌는지는 답변 머리에 적는다.
   - 클라우드 세션이라 연결할 수 없다면, 사용자 PC에서 Claude Desktop 앱 + Claude in Chrome으로 다시 실행하라고 한 줄로 안내한다.
   - 지금은 자료함 대신 사용자가 내려받아 올린 파일(HWP·PDF 등)을 쓴다. 추출은 [audit-issue-report 2단계](../audit-issue-report/SKILL.md)와 같다. 올린 파일에 비공개 표시가 있으면 내용을 답변에 쓰기 전에 [비공개 자료 확인](#비공개-자료-확인)을 거친다.
   - 뉴스 검색(4단계)은 그대로 진행한다.

## 3단계. 자료함 검색 (Chrome)

1. `tabs_context_mcp`로 Claude 탭 그룹을 확인한 뒤 **새 탭**을 열어 지원시스템 주소로 간다. Claude는 자기 탭 그룹 안의 탭만 볼 수 있으므로, 사용자가 따로 연 탭은 목록에 없어도 정상이다.
2. 로그인 화면이 나오면, Claude가 연 그 탭에서 사용자가 직접 로그인해 달라고 하고 기다린다. 아이디·비밀번호·인증번호를 대신 입력하거나 물어보지 않는다. 로그인했는데도 들어가지 못하면(예: "자료회원·직원회원·관리자 계정만") 계정 승인 문제라고 알리고, 2단계의 대체 방법으로 넘어간다.
3. 사이트 접근 허용 창이 뜨면 사용자가 허용할 때까지 기다린다. 거절하면 2단계의 대체 방법으로 넘어간다.
4. 프로필의 **자료함 위치**를 따라 자료함으로 간다. 지원시스템의 자료함은 왼쪽 메뉴 '의정활동 > 행감 자료실'이며, 기관별 자료함 카드(예: 주택실, 서울주택도시개발공사(SH))로 나뉘어 있다. 바로 [기관 카드 고르기와 검색](#기관-카드-고르기와-검색)을 따른다. 화면이 카드가 아니라 검색창 하나뿐이면 그 검색창에 검색어를 하나씩 넣는다.
5. 찾은 자료마다 `uijeong/knowledge/sakyowon-archive.md`의 '근거 표기 형식'대로 **카드 이름(화면 표기 그대로), 파일 이름(확장자까지 글자 그대로), 파일 크기, 읽은 쪽·표**를 기록한다. 자료 목록에는 등록일 칸이 없으므로 등록일은 '등록일 표시 없음'으로 쓴다. 결과가 많으면 최근 2년 안의 자료와 제목이 맞는 자료 순으로 모두 합쳐 5~10건을 고른다.
6. **비공개 자료 확인**: 고른 자료 가운데 비공개 자료가 있으면 본문을 열기 전에 [비공개 자료 확인](#비공개-자료-확인)을 거친다.
7. 고른 자료는 본문이나 미리보기를 `get_page_text`/`read_page`로 읽는다. 첨부파일만 있고 화면에서 읽을 수 없으면 목록만 남기고, 사용자에게 내려받아 올려 달라고 요청한다.
8. **읽기만 한다.** 글쓰기·수정·삭제·업로드·신청 버튼은 누르지 않는다. 특히 `uijeong/knowledge/sakyowon-archive.md`의 '누르지 않는 버튼'(자료함 만들기, 이름 바꾸기, 자료함 지우기, 파일 올리기, 의정소통에서 가져오기, 자료 줄의 ×)은 누르지 않는다. 확인 창(alert)이 뜰 만한 버튼도 피한다.
9. 같은 동작이 2~3번 실패하면 되풀이하지 말고, 무엇을 해 봤는지 알린 뒤 사용자에게 묻는다.

### 기관 카드 고르기와 검색

1. 자료실 첫 화면에서 카드마다 **기관 이름과 자료 건수**를 기록한다.
2. 질문 주제와 관련된 카드를 1~3개 고른다. `uijeong/knowledge/committee-2026.md`의 '소관 기관과 주요 업무' 표에서 주제가 어느 기관 업무에 걸리는지 보고 정한다.
   - 예: 공공임대·안심주택·청년주택 → 주택실 + SH / 정비사업·모아타운 → 주택실 (+ 대행이면 SH) / 공공건축·한강 개발 → 미래공간기획관 / 공공데이터·정보공개·AI 행정 → 디지털도시국 (+ 서울AI재단)
   - 감독하는 기관과 집행하는 기관이 나뉘면(예: 주택실이 SH를 지도·감독) 둘 다 고른다.
   - 표에 없는 카드는 이름으로 판단한다. 어느 카드인지 판단이 서지 않으면 AskUserQuestion으로 추천 카드를 첫째에 두고 묻는다.
3. 고른 카드를 누르고 그 안의 검색창에 검색어를 하나씩 넣는다. 카드 안에 검색창이 없으면 등록일 최신순으로 목록을 훑으며 제목으로 찾되, 카드당 5쪽까지만 본다.
4. 한 카드를 마치면 자료실 첫 화면으로 돌아가 다음 카드로 간다. 어느 카드에서 몇 건을 찾았는지(0건 포함) 기록해 답변 머리의 검색 범위에 적는다.
5. 고른 카드에서 하나도 찾지 못하면, 건수가 많은 카드 순으로 1~2개를 더 찾아본 뒤 멈추고 그 사실을 적는다.

### 비공개 자료 확인

비공개 자료를 열거나 답변에 쓰기 전에, 내부 규정상 외부 AI에 넣어도 되는지 사용자가 확인했는지 묻는다.

1. **비공개 자료로 보는 것**: 목록·본문·첨부에 "비공개", "부분공개", "대외비", "내부용", "열람 제한", "외부 유출 금지" 같은 표시가 있는 자료, 공개 여부 칸이 비공개인 자료, 일반인 개인정보가 담긴 자료. 표시가 애매하면 비공개로 본다.
2. 해당 자료를 모두 모아 **AskUserQuestion 한 번**으로 묻는다. 질문에 자료 제목과 비공개 표시를 적는다.
   - 질문: "아래 자료는 비공개로 표시되어 있습니다. 내부 규정상 외부 AI(Claude)에 넣어도 되는지 확인하셨나요?"
   - 선택지: **확인함 — 내용까지 사용** / **확인 안 함 — 제목·등록일만 사용** / **이 자료는 빼기**
3. 답을 받기 전에는 본문을 열거나 내용을 답변에 쓰지 않는다. 답이 없거나 애매하면 "제목·등록일만 사용"으로 처리한다.
4. 고른 결과를 답변 머리의 **비공개 자료** 칸에 적는다. 같은 대화에서 이미 답을 받은 자료는 다시 묻지 않는다.
5. "확인함"이어도 공유용으로 옮길 때는 7단계 규칙을 따로 따른다.

## 4단계. 뉴스 검색

1. WebSearch(`mode: "standard"`)로 검색어마다 찾는다. 결과가 부족하거나 오래되었으면 `extended`로 다시 찾는다. 같은 차례에 여러 검색을 함께 보낸다.
2. 포털에서만 보이는 지역 기사가 필요하고 Chrome이 연결되어 있다면, 네이버 뉴스 같은 포털 검색 결과를 Chrome 새 탭에서 읽는다.
3. 기사마다 **언론사, 날짜, 제목, 주소**를 기록한다. 같은 내용을 옮겨 쓴 기사는 하나로 묶고, 처음 보도한 기사를 대표로 남긴다.
4. 사설·칼럼·보도자료 받아쓰기는 일반 보도와 구분해 표시한다.

## 5단계. 답변 작성

[template.md](template.md) 구조를 따른다.

- **핵심 답변을 먼저** 쓴다. 3~5문장으로, 질문에 바로 답한다.
- 문장마다 출처를 단다. 자료함은 `[출처: 사교원 행감 자료실 > {카드 이름} > {파일 이름}, {쪽·표}]`, 뉴스는 `[언론사, 날짜]` 형식이다.
- **자료 성격을 구분**한다. 자료함 자료(공식·내부 자료)와 언론 보도가 다르게 말하면 "엇갈리는 부분"에 나란히 적고, 어느 쪽이 맞다고 단정하지 않는다.
- 두 출처 어디에도 없는 수치나 사실은 쓰지 않는다. 꼭 필요하면 `[확인 필요]`를 붙인다.
- 관점과 어조는 `profile.md`를 따른다. 이어서 쓸 만한 문서가 보이면 끝에 제안한다. 예: 행감 질의는 `/audit-issue-report`, 발언 원고는 `/floor-speech`, 제도화는 `/ordinance-draft`.

## 6단계. 자체 검수

- [ ] 답변의 모든 수치를 자료함 본문이나 기사 원문에서 다시 찾아 대조했다.
- [ ] 출처 목록의 주소가 실제로 읽은 페이지다(검색 결과 요약만 보고 쓰지 않았다).
- [ ] 자료함 자료와 뉴스를 섞어 하나의 출처처럼 쓰지 않았다.
- [ ] 비공개 자료는 사용자가 내부 규정 확인에 답한 범위 안에서만 썼다.
- [ ] 일반인 실명·연락처 같은 개인정보가 없다.
- [ ] 직접 연 탭은 닫았다. 사용자가 남겨 달라고 한 탭은 그대로 둔다.
- [ ] 위 확인을 마친 뒤 `CLAUDE.md`의 **검수 절차**대로 검수AI 랑랑별(`rangrang-byeol`)의 검수를 받고, 지적을 고친 뒤 문서 끝에 검수 기록을 붙였다.

## 7단계. 전달과 저장

1. 답변은 대화창에 바로 보여 준다. 끝에 "근거 자료를 열거나 출력하려면 '근거 n번 열어줘'라고 하세요"를 한 줄 붙인다. 요청이 오면 `uijeong/knowledge/sakyowon-archive.md` 5절대로 찾아 연다.
2. **답변은 항상 Markdown 파일로 저장한다.** 묻지 않고 `uijeong/outputs/research/YYYY-MM-DD-<주제>.md`에 저장하고(오늘 날짜), 저장한 경로를 알린다. 같은 날 같은 주제가 있으면 이름 끝에 `-2`, `-3`을 붙인다.
3. **자료함 자료는 내부 자료일 수 있다.** 그래서 `uijeong/outputs/research/`는 `.gitignore`로 GitHub에 올리지 않는 폴더로 두었다. 이 폴더의 파일을 `git add -f`로 억지로 올리거나 다른 폴더로 옮겨 커밋하지 않는다. 사용자가 공유용으로 옮겨 달라고 하면, 비공개 자료의 원문 인용이 들어가도 되는지 묻고, 안 되면 원문 인용 대신 요약과 자료 제목만 남긴 사본을 만든다.
4. 한글 파일이 필요하면 프로필의 **출력 형식**대로 변환한다: `python3 uijeong/scripts/md2hwpx.py <파일>.md`
